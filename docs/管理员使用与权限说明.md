# TodoList 管理员使用与权限说明

## 1. 初始管理员账号

### 1.1 默认账号

| 项目 | 默认值 |
|---|---|
| 用户名 | admin |
| 本地 Docker Compose 初始密码 | ChangeMe123! |
| 角色 | 管理员 |
| 默认成员 | member1、member2、member3、member4 |

安全要求：

- ChangeMe123! 只适用于本地开发或首次初始化示例，生产环境必须替换。
- 首次登录成功后，请立即进入“修改密码”修改管理员密码。
- 密码修改成功后，该账号在其他设备上的旧登录会话会立即失效。
- 不要把真实生产密码写入代码、README、ConfigMap、Dockerfile 或 Git。

### 1.2 CCE 环境的初始密码

CCE 不从文档中读取生产密码，实际密码由 CCE Secret 注入：

~~~text
deploy/cce/secret.yaml
  stringData.APP_BOOTSTRAP_ADMIN_PASSWORD
~~~

当前仓库只提供 deploy/cce/secret.example.yaml，其中的值是占位符。部署人员必须复制该文件为 secret.yaml，并将占位符替换为真实的首次管理员密码后再执行：

~~~powershell
kubectl apply -f .\deploy\cce\secret.yaml
~~~

CCE 中管理员初始用户名来自：

~~~text
deploy/cce/configmap.yaml
  APP_BOOTSTRAP_ADMIN_USERNAME: admin
~~~

如果数据库中已经存在 admin 用户，应用启动时不会重新设置其密码。因此，修改 Secret 中的初始密码不会自动重置已有管理员密码；已有账号应通过应用内修改密码或管理员用户管理功能处理。

## 2. 账号初始化规则

后端启动时由 BootstrapDataInitializer 初始化账号：

- 创建不存在的 admin 管理员账号。
- 创建不存在的 member1、member2、member3、member4 普通成员账号。
- 已存在的账号不会被覆盖，不会因应用重启而重置密码或角色。
- 可通过 APP_BOOTSTRAP_ENABLED=false 关闭启动时初始化。
- 初始化密码长度至少为 8 个字符。

本地 Docker Compose 的初始化配置位于：

~~~text
docker-compose.yml
  APP_BOOTSTRAP_ADMIN_USERNAME
  APP_BOOTSTRAP_ADMIN_PASSWORD
  APP_BOOTSTRAP_MEMBER_USERNAMES
  APP_BOOTSTRAP_MEMBER_PASSWORD
~~~

Spring Boot 的默认回退配置位于：

~~~text
backend/src/main/resources/application.yml
  app.bootstrap.admin-username
  app.bootstrap.admin-password
  app.bootstrap.member-usernames
  app.bootstrap.member-password
~~~

生产环境必须通过 CCE ConfigMap 和 Secret 覆盖这些回退值，不应依赖 application.yml 中的开发默认值。

## 3. 权限角色

系统目前有两个角色：

- ADMIN：管理员。
- MEMBER：普通成员。

### 3.1 权限对照表

| 功能 | 管理员 ADMIN | 普通成员 MEMBER |
|---|---|---|
| 查看全部任务 | 允许 | 允许 |
| 按分类、跟进人、状态筛选 | 允许 | 允许 |
| 查看甘特图 | 允许 | 允许 |
| 新增任务 | 可指定任意启用用户 | 只能新增自己负责的任务 |
| 修改自己的任务 | 允许 | 允许 |
| 修改他人任务 | 允许 | 禁止 |
| 修改未分配任务 | 允许 | 禁止 |
| 修改任务跟进人 | 允许 | 禁止 |
| 删除任务 | 允许 | 禁止 |
| 新增、修改、停用、启用分类 | 允许 | 禁止 |
| 查看启用分类 | 允许 | 允许 |
| 查看全部用户，包括停用用户 | 允许 | 禁止 |
| 查看启用用户 | 允许 | 允许 |
| 新增用户 | 允许 | 禁止 |
| 修改用户姓名、角色、启用状态 | 允许 | 禁止 |
| 重置其他用户密码 | 允许 | 禁止 |
| 修改自己的密码 | 允许 | 允许 |

所有权限由后端校验，前端隐藏按钮不等于权限授权。即使普通成员绕过页面直接提交 API 请求，后端也会返回 403。

## 4. 管理员操作说明

### 4.1 管理任务

管理员可以：

1. 新增任务并指定任意启用用户为跟进人。
2. 修改任务标题、日期、分类、跟进人、状态和进度。
3. 将任务重新分配给其他启用用户。
4. 删除任务。
5. 查看全部任务和甘特图。

任务更新使用 version 乐观锁。若两个用户同时编辑同一个任务，后提交且版本已过期的一方会收到 409 Conflict，需要刷新后重新编辑。

### 4.2 管理分类

管理员可以在分类管理页面：

- 新增分类。
- 修改分类名称、颜色和排序。
- 停用分类。
- 重新启用已停用分类。

停用分类不会删除历史任务；历史任务仍保留原分类。停用分类不能用于新建任务，重新启用后才会重新出现在任务表单中。

### 4.3 管理用户

管理员可以：

- 新增普通成员或管理员。
- 修改用户姓名。
- 修改用户角色。
- 停用或启用用户。
- 重置用户密码。

系统至少保留一个启用的管理员，最后一个管理员不能被降级或停用。

管理员重置其他用户密码后，该用户所有旧登录会话会失效。用户下次登录必须使用管理员设置的新密码，并建议登录后自行修改。

停用用户后，该用户不能登录；其历史任务和任务数据不会被删除。停用用户不能作为新任务的跟进人。

## 5. 普通成员操作边界

普通成员可以查看全部任务，便于团队协作，但只能编辑自己负责的任务。

普通成员新增任务时：

- 负责人自动设置为当前登录用户。
- 页面上的负责人选择器不可修改。
- 即使手动向后端提交其他用户 ID，也会被拒绝。

普通成员编辑任务时：

- 只能编辑当前 assignee 是自己的任务。
- 可以修改任务标题、日期、分类、状态和进度。
- 不能修改任务负责人。
- 不能编辑未分配任务或其他成员负责的任务。
- 不能删除任务。

## 6. 账号、密码和登录会话存储位置

### 6.1 配置文件中的初始账号密码

不同运行环境的初始配置位置如下：

| 环境 | 初始用户名位置 | 初始密码位置 |
|---|---|---|
| 本地 Java 默认启动 | backend/src/main/resources/application.yml 的默认配置 | 同一文件中的 app.bootstrap.admin-password 默认值 |
| 本地 Docker Compose | docker-compose.yml 的 APP_BOOTSTRAP_ADMIN_USERNAME | docker-compose.yml 的 APP_BOOTSTRAP_ADMIN_PASSWORD |
| CCE | deploy/cce/configmap.yaml 的 APP_BOOTSTRAP_ADMIN_USERNAME | deploy/cce/secret.yaml 的 APP_BOOTSTRAP_ADMIN_PASSWORD |

生产环境以 CCE Secret 为准。application.yml 中的 ChangeMe123! 只是开发回退值，不能作为生产密码管理方案。

### 6.2 数据库中的账号密码

初始化或新增用户后，账号信息存储在 TDSQL/MySQL 的 users 表：

| 字段 | 内容 |
|---|---|
| username | 登录用户名 |
| display_name | 显示姓名 |
| password_hash | BCrypt 密码哈希，不保存明文密码 |
| role | ADMIN 或 MEMBER |
| is_active | 是否允许登录和被分配任务 |
| session_version | 会话版本，用于使旧登录会话失效 |
| created_at / updated_at | 创建和更新时间 |

数据库表结构由 Flyway 创建，相关迁移文件位于：

~~~text
backend/src/main/java/db/migration/V1__TeamTodoSchema.java
backend/src/main/java/db/migration/V2__AddUserSessionVersion.java
~~~

管理员不应直接修改 users.password_hash。忘记密码时应使用管理员用户管理功能重置；需要数据库级应急处理时，必须由 DBA 按安全流程执行。

### 6.3 登录 Cookie 和会话

登录成功后，后端通过 HttpOnly Cookie 保存 JWT 会话，默认 Cookie 名称为 TODO_SESSION：

- Cookie 不由前端 localStorage 保存。
- JWT 中包含用户 ID、用户名和 sessionVersion。
- 修改密码或管理员重置密码时，数据库中的 session_version 增加。
- 旧 JWT 的版本不再匹配，因此所有旧会话失效。
- CCE HTTPS 环境应将 APP_AUTH_SECURE_COOKIE 设置为 true。

### 6.4 数据库连接密码

TDSQL 数据库账号密码不是 TodoList 用户密码，位置为：

~~~text
deploy/cce/secret.yaml
  stringData.DB_PASSWORD
~~~

该密码只用于后端连接 TDSQL，必须与 TDSQL 中 todo_app 账号的密码一致。不要把它与 APP_BOOTSTRAP_ADMIN_PASSWORD 混用。

## 7. 密码修改和重置流程

### 管理员修改自己的密码

1. 使用 admin 登录。
2. 打开右上角用户菜单。
3. 选择“修改密码”。
4. 输入当前密码和新的 8–100 位密码。
5. 修改成功后重新登录。

### 管理员重置成员密码

1. 进入用户管理。
2. 找到需要处理的用户。
3. 使用编辑或重置密码操作设置临时密码。
4. 通知用户使用临时密码登录。
5. 用户登录后立即修改为个人密码。

### 忘记管理员密码

优先联系其他启用的管理员重置密码。如果系统只有一个管理员且密码丢失，不要直接删除数据库用户；应先备份 TDSQL，并由具有数据库权限的运维人员按企业流程生成 BCrypt 哈希后处理，或临时通过安全的应用维护流程恢复账号。
