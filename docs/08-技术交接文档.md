# TodoList 技术交接文档

## 1. 系统架构

~~~text
企业内网用户
  -> CCE 内网 ELB + Ingress
     /              -> todo-frontend Service -> Vue Node 静态服务器
     /api           -> todo-backend Service  -> Spring Boot API
                                              -> 外部 TDSQL
~~~

前端和后端在同一 CCE 命名空间中分别部署，Service 类型为 ClusterIP。浏览器使用相对路径 /api，不需要浏览器端配置固定后端地址。

## 3. 本地构建和运行

### 前端

~~~powershell
cd frontend
npm ci
npm run lint
npm run test
npm run build
~~~

### 后端

~~~powershell
cd backend
mvn -B test
mvn spring-boot:run
~~~

### 完整本地环境

~~~powershell
docker compose up --build
~~~

本地入口为 http://localhost:8081，后端端口为 8080，本地数据库端口为 3306。

## 4. REST API

除登录接口、健康接口外，其余接口需要 HttpOnly Cookie 登录。

| 方法 | 路径 | 权限 | 用途 |
|---|---|---|---|
| POST | /api/auth/login | 未登录 | 登录 |
| GET | /api/auth/me | 已登录 | 获取当前用户 |
| POST | /api/auth/logout | 已登录 | 退出 |
| POST | /api/auth/change-password | 已登录 | 修改自己的密码 |
| GET | /api/users | 已登录 | 查看启用用户 |
| GET | /api/users?includeInactive=true | 管理员 | 查看全部用户 |
| POST | /api/users | 管理员 | 创建用户 |
| PATCH | /api/users/:id | 管理员 | 修改用户、停用或重置密码 |
| GET | /api/categories | 已登录 | 查看启用分类 |
| GET | /api/categories?includeInactive=true | 管理员 | 查看全部分类 |
| POST | /api/categories | 管理员 | 创建分类 |
| PATCH | /api/categories/:id | 管理员 | 修改或启用分类 |
| DELETE | /api/categories/:id | 管理员 | 停用分类 |
| GET | /api/tasks | 已登录 | 查询任务 |
| POST | /api/tasks | 已登录 | 创建任务 |
| PATCH | /api/tasks/:id | 管理员或负责人 | 修改任务 |
| DELETE | /api/tasks/:id | 管理员 | 删除任务 |
| GET | /api/health | 公开 | API 健康检查 |

任务更新必须携带当前 version。版本不一致返回 409 Conflict。

## 5. 环境变量

### 数据库

| 变量 | 用途 | 来源 |
|---|---|---|
| DB_HOST | TDSQL 主机 | ConfigMap |
| DB_PORT | TDSQL 端口 | ConfigMap |
| DB_NAME | 数据库名 | ConfigMap |
| DB_USER | 数据库账号 | ConfigMap |
| DB_PASSWORD | 数据库密码 | Secret |
| DB_SSL | 是否启用 SSL | ConfigMap |
| DB_POOL_MAX_SIZE | 连接池上限 | ConfigMap，可选 |

### 认证

| 变量 | 用途 | 来源 |
|---|---|---|
| APP_AUTH_JWT_SECRET | JWT 签名密钥，至少 32 字节 | Secret |
| APP_AUTH_COOKIE_NAME | Cookie 名称 | ConfigMap |
| APP_AUTH_SESSION_HOURS | 会话有效期 | ConfigMap |
| APP_AUTH_SECURE_COOKIE | HTTPS Cookie 开关 | ConfigMap |

### 初始化账号

| 变量 | 用途 | 来源 |
|---|---|---|
| APP_BOOTSTRAP_ENABLED | 是否启动初始化账号 | ConfigMap |
| APP_BOOTSTRAP_ADMIN_USERNAME | 管理员用户名 | ConfigMap |
| APP_BOOTSTRAP_ADMIN_PASSWORD | 管理员初始密码 | Secret |
| APP_BOOTSTRAP_MEMBER_USERNAMES | 成员用户名列表 | ConfigMap |
| APP_BOOTSTRAP_MEMBER_PASSWORD | 成员初始密码 | Secret |

## 6. 数据模型

核心数据表：

| 表 | 用途 |
|---|---|
| users | 用户、角色、BCrypt 密码哈希、启用状态和会话版本 |
| task_categories | 任务分类、颜色、排序和启用状态 |
| tasks | 标题、日期、分类、负责人、状态、进度和乐观锁版本 |
| flyway_schema_history | Flyway 迁移记录 |

任务状态：

- NOT_STARTED：未开始。
- IN_PROGRESS：进行中。
- COMPLETED：已完成。

## 7. 安全设计

- 密码使用 BCrypt 哈希，不保存明文。
- 登录 JWT 放在 HttpOnly Cookie。
- 密码修改或管理员重置密码会增加 session_version，使旧会话失效。
- 后端重新执行权限校验，不信任前端隐藏按钮。
- CCE Service 使用 ClusterIP。
- 生产访问应通过内网 Ingress。
- 生产 Secret 不进入 Git。
- 数据库结构由 Flyway 管理，Hibernate 只做 validate。

## 8. 数据库迁移

迁移文件：

~~~text
backend/src/main/java/db/migration/V1__TeamTodoSchema.java
backend/src/main/java/db/migration/V2__AddUserSessionVersion.java
~~~

首次部署和数据库版本升级由 migration Job 执行，普通后端 Deployment 设置 SPRING_FLYWAY_ENABLED=false。升级前先备份 TDSQL，迁移成功后再发布应用。

## 9. CCE 资源关系

~~~text
todo-internal
  ├─ ConfigMap todo-config
  ├─ Secret todo-secrets
  ├─ Job todo-migration
  ├─ Deployment todo-backend
  ├─ Service todo-backend:8080
  ├─ Deployment todo-frontend
  ├─ Service todo-frontend:8080
  └─ Ingress todo-internal
~~~

Kustomization 当前不自动包含 migration-job.yaml，避免普通发布重复创建同名 Job。首次部署和数据库变更时显式 apply 该 Job。

## 11. 技术问题定位顺序

1. 浏览器是否能访问内网域名。
2. Ingress Host、Ingress Class 和路径是否正确。
3. 前端 Service 和 Pod 是否健康。
4. 后端 Service、Pod 和 readiness 是否健康。
5. 后端日志是否有 TDSQL 连接或 Flyway 错误。
6. TDSQL 白名单、安全组、账号权限和 SSL 是否正确。
7. Secret 和 ConfigMap 是否已更新并触发后端滚动重启。
